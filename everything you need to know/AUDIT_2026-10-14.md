## 4. Trained-model plan

**Blocker:** confirm with faculty whether a fine-tuned **classifier** is acceptable or a **generative** fine-tune (LoRA/PEFT) is required. Everything below assumes a classifier.

- **Task:** a sentence-level, multi-label requirement classifier with labels `FUNCTIONAL`, `NON_FUNCTIONAL`, `CONSTRAINT`, `ASSUMPTION`, `NEEDS_CLARIFICATION`. Multi-label because one sentence can be both a constraint and ambiguous. Write the annotation guide before labelling anything.
- **Data:** split the 32 briefs in `apps/api/evaluation/requirements_dataset.json` into sentences as a seed, then add public requirement sets (for example the PROMISE NFR dataset; check its licence) and team-written briefs. Target 800–1,500 labelled sentences. Split by **brief**, not by sentence, to avoid leakage.
- **Model:** fine-tune `distilbert-base-uncased` (or `microsoft/deberta-v3-small`) with Hugging Face Transformers. A free Colab T4 trains this in minutes. Baseline: TF-IDF + logistic regression.
- **Report:** per-label precision/recall/F1, macro F1, a confusion matrix per label, and an error analysis. Record the seed, hyperparameters, and checkpoint hash.
- **Integration point:** `RequirementsPipelineService.analyze` in `apps/api/app/services/requirements_pipeline.py`:
  1. Split the brief into sentences.
  2. Run them through a new `app/ml/requirement_classifier.py`, loaded lazily on CPU and failing gracefully.
  3. Store the labels, confidences and model version per sentence.
  4. Pass them to the LLM prompt as evidence.
  5. Show them in the analysis UI as "classifier suggestions".

  Inference must not crash the analysis when artifacts are missing; it reports `classifier: unavailable` instead. Prefer ONNX Runtime or CPU-only torch so the API image stays small.
- **Tests:** a unit test using a tiny fixture model, plus a pipeline test asserting that the classifier is called and its output persisted.

## 6. Risks that could block the faculty demo

1. **No trained model.** Mandatory, and it needs data labelling time, not just code. Start now, in parallel with the fixes.
2. **The agent and approval flow** (BUG-01/02) are the "AI that executes" story. Neither works today.
3. **Fabricated requirements** (BUG-05). An examiner pasting an unrelated brief will see "iOS 15+ / PCI-DSS" requirements.
4. **A fresh-machine setup fails** (BUG-03, BUG-13). Rehearse the demo setup on a clean database.
5. **No real LLM has been tested end to end.** All AI results above came from the mock provider.
6. **The SRS isn't in the repo**, so coverage can't be checked line by line.
